# java-calculator-precourse - [BE] 조상준


# 1. 어플리케이션 정의

---

## 용어 정의

| 한글이름 | 영문이름 | 설명                                                                                |
| --- | --- |-----------------------------------------------------------------------------------|
| 문자 | char | 문자 하나를 의미한다.                                                                      |
| 문자열 | string | 문자 2개 이상으로 구성된 문자열을 의미한다.                                                         |
| 구분자 | delimiter | 구분자를 의미한다. 모든 구분자는 단수이다.                                                          |
| 기본 구분자 | default delimiter | 쉼표(,) 또는 콜론(:)만을 의미한다.                                                            |
| 커스텀 구분자 | custom delimiter | 사용자가 지정한 구분자를 의미한다.                                                               |
| 빈 문자 | empty string | “”를 의미한다. (참고: 문자임에도 코드 작성시에 char타입에 `''`를 지정할 수 없기에, 예외로 empty `string` 으로 표기한다.) |
| 공백 문자 | whitespace char | 공백 문자 1개로 구성된 문자를 의미한다.                                                     |
| 공백 문자열 | whitespace string | 2개 이상 연속된 공백으로 구성된 문자열을 의미한다.                                                     |

## 사용자 입력 규칙

### 구분자 검증 규칙

---

1. **커스텀 구분자는 반드시 한 글자(char)이어야 한다.**
    - 근거: 요구사항에서 문자열과 문자라는 용어를 함께 사용하며, 커스텀 구분자를 `문자열`이 아닌 `문자`로 표기하고 있기 때문이다.
    - 예시: 입력 //;;\n1;;2;;3 → `IllegalArgumentException` 발생
2. **한번의 요청에서 커스텀 구분자는 하나만 지정할 수 있다.**
3. **공백(” “)도 유효한 커스텀 구분자가 될 수 있다.**
    - 따라서, 입력한 문자열 내 모든 공백은 정제되지 않고 문자로 인식한다.
    - 예시1:  입력 // \n1 2 3 → 출력 6
    - 예시2: 입력 1, 2,3 → `IllegalArgumentException` 발생 (공백을 커스텀 구분자로 지정하지 않았기 때문)
4. **빈 문자(””)는 커스텀 구분자가 될 수 없다.**
    - 근거: 요구사항에서 `“” → 0`을 출력한다. 따라서 비어있는 토큰인 빈 문자(””)는 0으로 인식한다.
    - 예시: //\n1,2,3 → `IllegalArgumentException` 발생
5. **구분자는 문자열 내에서 연속으로 등장할 수 있다.**
    - 근거: 규칙 4에 의해 연속된 구분자 사이의 빈 문자(비어있는 토큰)는 0으로 인식하기 때문이다.
    - 예시: 입력 1,,2 → 출력 3
6. **문자열 맨 앞/뒤에 구분자가 위치할 수 있다.**
    - 근거: 규칙4,5에 기반하여 빈 문자는 0으로 인식한다. 따라서 문자열 맨앞/맨뒤의 구분자의 앞/뒤에는 0이 있다고 인식한다.
    - 예시: 입력 ,1,2, → 0+1+2+0 → 출력 3
7. **커스텀 구분자 지정 시에 기본 구분자(쉼표, 콜론)를 사용할 수 없다.**
    - 근거: 요구사항에 “앞의 기본 구분자(쉼표, 콜론) `외에` 커스텀 구분자를 지정할 수 있다.” 라고 명시되어 있다.
    - 예시: 입력 //,\n1,2,3 → `IllegalArgumentException` 발생
8. **숫자는 커스텀 구분자가 될 수 없다.**


### 2. 숫자 검증 규칙

---

1. 모든 숫자는 양의 정수여야 한다.
2. 숫자는 int의 양의 정수 범위를 초과할 수 없다.
    - 0 ≤ n ≤ 2,147,483,647
3. 빈 문자(””)인 비어 있는 토큰은 0으로 인식한다.
4. 연속하지 않는 숫자는 독립적인 숫자로 인식한다.

# 기능 명세

---

- 아래 기능 명세는 어플리케이션의 입력 → 출력 흐름 순서에 맞춰 작성되었습니다.
   - 따라서 모든 기능은 별도의 언급이 없는 경우, 선행 기능의 검증이 통과되었을 때만 실행됩니다.
- 정상적인 입력에서 입력 문자열의 구성요소를 다음과 지칭합니다.
   - `헤더`: 문자열 맨 앞에 나오는 `//{구분자}\n` 를 의미한다.
   - `바디`: 헤더 이외의 모든 파트를 의미한다.
- 첨언: 따라서, 커스텀 구분자를 지정하지 않은 정상적인 입력은 헤더가 없는 것으로 간주합니다.

## 검증에 대한 설명

- 해당 어플리케이션은 총 3가지 대상에 대한 유효성 검증이 이뤄집니다.
- 각 3가지 대상에 대한 검증 기능은 총 4가지이며, 각 검증은 검증1, 검증2, 검증3, 검증4로 표현합니다.
   - 검증1: 전체 문자열 유효성 검증
   - 검증2: 헤더 후보 문자열 유효성 검증
   - 검증3: 바디의 문자 토큰 유효성 검증
   - 검증4: 바디의 숫자 토큰 유효성 검증

## 전체 기능

- [x]  사용자는 문자열을 입력한다.
- [ ]  검증1. 입력된 전체 문자열 포멧 검증
   - [ ]  빈 문자인 경우, 0을 출력한다.
- [x]  입력된 문자열에 헤더 존재 가능성을 확인한다.
   - 첨언: 존재 가능성은 문자열의 첫 시작 연속 문자가 //인 경우로 명칭하며, 이후 총 5개의 연속된 문자를 파싱하여 이 대상자를 기준으로 바로 다음 기능을 수행한다. (이 5개 토큰으로 구성된 부분은, `헤더 후보 문자열`이라고 명칭한다.)
- [x]  검증2. 헤더 후보 문자열의 포멧 검증
   - 첨언: 해당 검증은 헤더 후보 문자열이 존재하는 경우만, 실행된다.
   - [x]  헤더는 다음과 같은 형식을 준수한다. `//{문자}\n`
   - [x]  헤더의 길이는 5글자이다.
   - [x]  헤더 내부에 작성된 커스텀 구분자는 1글자이다.
   - [x]  헤더 내부에 작성된 커스텀 구분자는 숫자일 수 없다.
   - [ ]  헤더 내부에 작성된 커스텀 구분자는 기본 구분자일 수 없다.
- [x]  헤더가 존재하는 경우, 커스텀 구분자 파싱 및 `지정된 구분자` 저장 
   - 첨언: 커스텀 구분자가 있는 경우 지정된 구분자는 3개, 없는 경우 기본 구분자들인 2개로 구성된다.
- [x]  입력에서 바디를 파싱하여, 바디 내부의 각 토큰을 검증한다.
   - [x]  검증3. 바디의 각 토큰 유효성 검증
      - 첨언1. 바디 내부의 각 토큰이 `지정된 구분자` 혹은 숫자인지 검증한다.
      - 첨언2. 이때, 빈 공백 (“ “)도 토큰으로 취급되어 검증된다.
- [x]  바디를 `숫자가 아닌 문자`를 기준으로 분리하여 숫자를 저장한다.
   - 첨언. 따라서 연속된 숫자는 하나의 숫자로 판단한다.
- [x]  검증4. 숫자 유효성 검증
   - [x]  각 숫자의 값은, `1 ≤ n ≤ 2,147,483,647 (n은 정수)`에 속하는 양의 정수여야 한다.
- [ ]  숫자들을 모두 합계한다.
- [ ]  합계된 결과 값을 사용자에게 출력한다.
