# java-calculator-precourse - [BE] 조상준


# 1. 어플리케이션 정의

---

## 용어 정의

| 한글이름 | 영문이름 | 설명                                                                                |
| --- | --- |-----------------------------------------------------------------------------------|
| 문자 | char | 문자 하나를 의미한다.                                                                      |
| 문자열 | string | 문자 2개 이상으로 구성된 문자열을 의미한다.                                                         |
| 구분자 | delimiter | 구분자를 의미한다. 모든 구분자는 단수이다.                                                          |
| 기본 구분자 | default delimiter | 쉼표(,) 또는 콜론(:)만을 의미한다.                                                            |
| 커스텀 구분자 | custom delimiter | 사용자가 지정한 구분자를 의미한다.                                                               |
| 빈 문자 | empty string | “”를 의미한다. (참고: 문자임에도 코드 작성시에 char타입에 `''`를 지정할 수 없기에, 예외로 empty `string` 으로 표기한다.) |
| 공백 문자 | whitespace char | 공백 문자 1개로 구성된 문자를 의미한다.                                                     |
| 공백 문자열 | whitespace string | 2개 이상 연속된 공백으로 구성된 문자열을 의미한다.                                                     |

## 사용자 입력 규칙

### 구분자 검증 규칙

---

1. **커스텀 구분자는 반드시 한 글자(char)이어야 한다.**
    - 근거: 요구사항에서 문자열과 문자라는 용어를 함께 사용하며, 커스텀 구분자를 `문자열`이 아닌 `문자`로 표기하고 있기 때문이다.
    - 예시: 입력 //;;\n1;;2;;3 → `IllegalArgumentException` 발생
2. **한번의 요청에서 커스텀 구분자는 하나만 지정할 수 있다.**
3. **공백(” “)도 유효한 커스텀 구분자가 될 수 있다.**
    - 따라서, 입력한 문자열 내 모든 공백은 정제되지 않고 문자로 인식한다.
    - 예시1:  입력 // \n1 2 3 → 출력 6
    - 예시2: 입력 1, 2,3 → `IllegalArgumentException` 발생 (공백을 커스텀 구분자로 지정하지 않았기 때문)
4. **빈 문자(””)는 커스텀 구분자가 될 수 없다.**
    - 근거: 요구사항에서 `“” → 0`을 출력한다. 따라서 비어있는 토큰인 빈 문자(””)는 0으로 인식한다.
    - 예시: //\n1,2,3 → `IllegalArgumentException` 발생
5. **구분자는 문자열 내에서 연속으로 등장할 수 있다.**
    - 근거: 규칙 4에 의해 연속된 구분자 사이의 빈 문자(비어있는 토큰)는 0으로 인식하기 때문이다.
    - 예시: 입력 1,,2 → 출력 3
6. **문자열 맨 앞/뒤에 구분자가 위치할 수 있다.**
    - 근거: 규칙4,5에 기반하여 빈 문자는 0으로 인식한다. 따라서 문자열 맨앞/맨뒤의 구분자의 앞/뒤에는 0이 있다고 인식한다.
    - 예시: 입력 ,1,2, → 0+1+2+0 → 출력 3
7. **커스텀 구분자 지정 시에 기본 구분자(쉼표, 콜론)를 사용할 수 없다.**
    - 근거: 요구사항에 “앞의 기본 구분자(쉼표, 콜론) `외에` 커스텀 구분자를 지정할 수 있다.” 라고 명시되어 있다.
    - 예시: 입력 //,\n1,2,3 → `IllegalArgumentException` 발생
8. **숫자는 커스텀 구분자가 될 수 없다.**


### 2. 숫자 검증 규칙

---

1. 모든 숫자는 양의 정수여야 한다.
2. 숫자는 int의 양의 정수 범위를 초과할 수 없다.
    - 0 ≤ n ≤ 2,147,483,647
3. 빈 문자(””)인 비어 있는 토큰은 0으로 인식한다.
4. 연속하지 않는 숫자는 독립적인 숫자로 인식한다.
